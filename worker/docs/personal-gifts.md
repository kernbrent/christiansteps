# Personally received ministry gifts

Local implementation, not released. Apply CSM DB migration 0005 before application use. No CSM LEDGER_DB migration. Deploy compatible HS receiver and identity authority before CSM, only after explicit authorization. Existing PayPal and JBB flows remain unchanged. Testing must use mocked bindings or a separately configured CSM test environment pointing only at HS test resources; never connect CSM production to a test donor directory or vice versa.

The authenticated /personal-gifts routes use CSM giving permission, CSRF, and allowed-origin validation. /contacts proxies the named CsmIdentity entrypoint and authenticates the real CSM session; the authority additionally requires HS membership and contacts read permission. Only ID, name, email, and phone are returned, with a 30-result search limit. Caller-supplied user IDs cannot grant access.

Migration 0005 stores immutable original gifts, cent-based settlements, private R2 evidence metadata, revisions, frozen outbound payloads, and append-only audit entries. Original-payment method/holder/reference and stable request IDs prevent duplicate entries. Settlement guards reject stale changes and over-allocation atomically. Fees and expenses require supporting evidence before send; all funds must reconcile and transfers must have clearance dates. Evidence supports up to 20 PNG/JPEG/PDF files of at most 5 MB. Gift evidence is private and locked when sending; no public file URL exists.

Personal delivery uses the existing HS private authenticated inbox transport with explicit PERSONAL_GIFT event and validated personalGift metadata. It does not fabricate paypal_transactions rows. Legacy payload/database field names paypalTransactionId and paypal_event_code carry the personal gift UUID and PERSONAL_GIFT discriminator for compatibility. CSM and HS copies of both contract files must stay identical. The personal event is valid only for received USD HS gifts and reconciled settlement metadata. JBB cannot receive this event.

The original HS contact ID is preserved through approval. HS records net income with the gross charitable amount and actual personal payment method. Expenses are separate admin-entered ledger rows keyed to unique settlement IDs, inserted in the same approval transaction; bank transfers do not create new income. Original source evidence stays in CSM and is identified by gift ID in HS. Existing donor contact information and unrelated history are not overwritten. Fees reduce net income without reducing gross donor credit. Approval callbacks and retries update the CSM status; terminal approval/denial cannot be downgraded by a delayed response.

The dedicated reconciliation and CSV report include original donor, holder, original gift, settlement amounts, bank references, and remaining funds. These are supplemental custody records, not automatic CSM general-ledger bank imports. HS-approved personal gifts join CSM giving-letter data using the original donor and date, with Christian Steps Ministries — Hope Sojourns identification and the actual payment method. Source gift records and donor statement records must not be added as separate contributions.

Operational guide: personally-received-gifts-process.md and /admin/personal-gifts/process.html. Before send, corrections use audited reversals and voids. Sent records remain locked for coordinated review; this version does not automatically reverse an already approved HS gift.

Validation covers selected donor vs holder, HS access restrictions, duplicate saves, movement retries, partial transfers, allocation limits, shared deposit references, delivery retries, final callbacks, source locking, evidence requirements, void/reverse history, original-donor statements, JBB rejection, atomic HS income/expense approval, and duplicate approval.
